# Security Policy

## Supported Versions

Currently, only the main deployment of the interactive portfolio is actively supported for security updates. 

| Version | Supported          |
| ------- | ------------------ |
| v1.0.x  | :white_check_mark: |
| < v1.0  | :x:                |

## Reporting a Vulnerability

Security is a top priority for this project. We take vulnerabilities seriously and appreciate the efforts of security researchers and the broader open-source community to help us keep this project safe.

If you discover a security vulnerability within this project, please follow these guidelines:

1. **Do not create a public GitHub issue.** Instead, please send an email to **pandadebdatta9@gmail.com** with the subject line `[SECURITY VULNERABILITY]`.
2. Include a detailed description of the vulnerability, including steps to reproduce it.
3. If possible, provide a proof-of-concept (PoC) or script that demonstrates the vulnerability.
4. Provide your contact information so we can reach out to you if we need further details.

### Response Time

You can expect an acknowledgment of your report within 48 hours. After triage, we will provide an estimated timeline for a patch. We will keep you informed of our progress throughout the remediation process.

### Disclosure Policy

We ask that you allow us a reasonable amount of time (typically 90 days) to resolve the issue before disclosing it publicly. Once the vulnerability has been patched, we will publicly acknowledge your contribution in our release notes (unless you prefer to remain anonymous).

Thank you for helping to keep this project secure!
